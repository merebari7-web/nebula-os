Nebula OS — Accessibility & Security Statement

Conformance, design decisions and known limitations for the Nebula OS web operating system. Reviewed against WCAG 2.1 Level AA, the current standard referenced by Section 508 of the Rehabilitation Act, and common federal web-hosting security baselines.

1. Accessibility conformance

Nebula OS is a single-page desktop environment. The table below summarizes the accessibility implementation shipped in the current release.

Requirement (WCAG 2.1 AA)StatusImplementation
1.4.3 Contrast (minimum) Implemented Body, muted, danger and gold-on-navy text pairs verified at ≥ 4.5:1. Button text color is computed at runtime against the user's accent color and set to the option with the higher contrast ratio (--btn-ink), so custom accent choices cannot drop text below standard.
1.4.11 Non-text contrast Implemented Focus indicators use a 2 px accent outline (3 px in TV Mode); window chrome, traffic lights and dock states use strokes above the 3:1 recommendation.
2.1.1 Keyboard Implemented Complete keyboard operation: arrow keys move a focused window, Shift+arrows resize it; menubar menus navigate with arrow keys (Down/Up between items, Left/Right between menus, Enter to run, Esc to close); desktop icons, dock, start menu, calculator, files and lock screen are all keyboard reachable. TV Mode is fully remote-operable with arrow keys, Enter and Esc.
4.1.2 Name, role, value Implemented Menubar menus expose role=menu/menuitem, dialogs expose role=dialog aria-modal, notifications render into a role=status live region, and a second polite live region announces OS events (window opened/closed, screen locked) to screen readers. Icon-only buttons carry aria-labels.
2.3.3 Animation from interactions Implemented Settings → Behavior → “Reduce Motion” (and the in-OS setting) collapses all animation and transition durations to a single frame and disables the fireworks show, which reports why it is disabled. A native prefers-reduced-motion fallback is applied on this page.
3.1 Language of page Implemented <html lang> is kept in sync with the selected UI language (8 languages, including full RTL for Arabic).
Pointer-dependent interactions (mouse-only drag/resize) Partially addressed Dragging and edge-resizing remain pointer gestures (standard for desktop environments), but every window can be moved and resized from its title bar with the keyboard, so no functionality depends on a mouse.

2. Security design

  • Content Security Policy. A strict CSP is delivered on every page: script-src 'self' (no inline or remote script, no eval — the shell math engine is a dedicated parser, not eval), no plugins (object-src 'none'), locked base-uri and form-action. Frame embedding is restricted to https: and is used only by the documented web-bridge (TV/streaming and Android) features; the OS itself loads no third-party scripts.
  • Session PIN. The lock-screen PIN is never stored in cleartext. It is stored as a salted SHA-256 digest (unique 16-hex-digit salt per PIN); legacy cleartext values are transparently migrated and discarded at boot.
  • Audit trail. A local, capped (500-entry) audit log records boot, app open/close, lock/unlock, PIN changes, theme/wallpaper changes, file import/export, Android installs/uninstalls, TV launches and data wipes. It is viewable in the Audit Log app, exportable as JSON, and clearable only after explicit confirmation.
  • Auto-lock. The screen locks after configurable idle time (default 5 minutes), configurable or disabled in Settings → Security.
  • Data locality. All user data (files, settings, PIN hash, audit log) lives in this browser's local storage. Nothing is transmitted to a server. The only outbound connections are: the Google Fonts stylesheet, and the documented live-data APIs (CoinGecko for the Stocks app, Photon for Maps geocoding, YouTube oEmbed), each listed in the CSP connect-src.
  • Input handling. All dynamic content is HTML-escaped before insertion; user-supplied file names, notes and terminal output never execute as code. Terminal “math” and assistant arithmetic use a bounded expression parser that cannot access functions, objects or the environment.

3. Known limitations (stated plainly)

Third-party embedded content. When a TV or Android web-bridge embeds an external site, that site's own accessibility and security posture is outside Nebula OS's control. Embedding is always optional — the same content can be opened in its own tab.
Browser trust model. Nebula OS runs inside a browser tab and inherits the browser's sandbox. It does not provide full-disk encryption, hardware key authentication, or CAC/PIV card support. It is not a substitute for an approved endpoint security product.
Mobile browsers. TV Mode and the full desktop work best on desktop and tablet form factors. Mobile is supported (safe-area aware layout, touch targets ≥ 44 px) but some power features (window dragging) are pointer-centric.
No biometric integration. Authentication is PIN-only. WebAuthn/passkey integration is not part of the current release.

4. Feedback

Report accessibility or security findings through the project's issue tracker at github.com/merebari7-web/nebula-os. Reports that include steps to reproduce (keyboard path or AT configuration) are triaged first.
